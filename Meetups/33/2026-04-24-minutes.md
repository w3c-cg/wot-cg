### Meetup Presentation

Ege: Today Roman Binkert presents his findings about autonomous agents communicating in a cyber-physical environment.

Roman: The motivation for this work is the following scenario. Consider a robot arm that wants to move an object. How would it know about the presence of an object? It would need to communicate with a sensor.

Roman: The communication and capability discovery are handled by WoT. The sensor has a TD and the robot can use it.

Roman: When you scale (e.g. adding another robot arm or more objects), you increase the problem of having different interaction models. Again, this can be solved by WoT.

Roman: Multi-agents have autonomy and self-organization, but lack interoperability. WoT can help in this sense.

Roman: The central part of the WoT is the Thing Description. It is used to describe how you can interact with the device.

Roman: In a TD you can describe affordances: what a Thing can do in its environment.

Roman: We have properties, actions, and events.

Roman: Agents (a very hot buzzword now) — in our use case we refer to agents in the context of agentic programming. Agentic programming is another way of programming devices. You don't use regular structured instructions; you describe a high-level goal and let the agent figure out how to achieve it.

Roman: Each agent starts from sensors, then uses a set of beliefs and desires to operate.

Roman: The idea of this work is to match Agent Speak to WoT interaction affordances. We use TD to describe agents' capabilities.

Roman: For mapping:

- When ask -> read/observe a property or subscribe to an event
- When achieve -> invoke an action
- tell -> write a property or use the "tell" action
- askHow is a particular action

Roman: We use `@type` in the TD to do mapping between affordances and plans.

> Roman showing a real-world example

Roman: That concludes my presentation about how to use WoT in an agent-to-agent scenario to create protocol-agnostic agentic applications.

## Q&A

Alexandru: Suppose that the red or blue cube has a particular ontology. The meaning of an operation (affordance) can be described in an ontology or natural language. How do you align different ontologies when dealing with inputs or outputs in the TD?

Roman: Maybe using an LLM we can create this alignment. In our approach, we didn't use it.

Simon: Agents are different from Things. One strong difference is that an agent might refuse to perform an operation. Agency is the capability of deciding based on its own goals. This mapping seems to override that capability, making an agent effectively a Thing.

Roman: This is something we can definitely improve as future work. The real purpose of the work is the mapping.

Simon: This is basically creating special actions that have special meaning, which is something we should avoid with WoT.

Antonie: what is an agent or a tool? Robotic arm agents?

Roman: Each arm has an agent that controls them.

JLemee: It is not clear how the mapping works. Is the mapping happening at compile time or runtime?

Roman: I need some atomic step in a scenario; those steps can be rearranged or even renamed to achieve a bigger plan.

Ben: You talk about protocol-agnostic communication between agents and things. When it comes to actually activating a particular affordance, the agents need to implement all different protocols. Do you think that a new web-native protocol would help?

Roman: We used node-wot. Our framework just activates an affordance; it uses node-wot.

Ben: Does your agent use scripting API?

Roman: yes.

Andrei: It is definitely an interesting initiative. We have a similar approach. How does the interaction between the agents happen? In particular, how are these plans transferred? Is there a possibility to "split" the actions? In other words, if one agent is capable of a complex action, another might need multiple atomic simpler actions.

Roman: About your last question, if this is the case we need a way to describe it.

Andrei: Thanks a lot, nice job. How do you position the approaches with Eclipse LMOS or the A2A protocol? Are you looking at heterogeneous types of agents? Your agent model is not always applicable.

Roman: LLMs are difficult to describe with a TD; we need some other mechanism. Maybe some different abstraction layers.

Roman: AskHow is special, but tell is not. To achieve interoperability, of course, we need to agree on using TD and therefore a similar model.

Andrei: Information protocol and hypermedia based interaction for thing description.

Cristiano: This special AskHow action — could it ever be introduced as a native WoT operation inside the WoT interaction model?
